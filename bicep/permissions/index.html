    Permissions

    This reference describes the default Agent Application layout: hosted-no-panel, with the agent runtime in Foundry Agent Service and the frontend in Azure Container Apps. There is no orchestrator Container App, application panel or application Cosmos DB in this layout. Native Foundry IQ ingestion is selected by default; Agent App Ingestion is optional. Foundry's own backing resources are separate from application data stores.

    The full-stack runbook provisions the composed layout, not the raw root parameters alone. Custom definitions, optional services and reused resources can change the assignments below. Inspect the selected environment's effective principals and scopes before granting access.

    Keep the identities separate

    Principal Purpose
    Deployment operator or pipeline Creates resources, publishes configuration, builds images and deploys agent versions.
    Frontend managed identity Reads UI settings/secrets, pulls its image and accesses Blob references. It is not the signed-in user.
    Foundry project managed identity Pulls the hosted image and uses configured project connections. It is not the running agent's identity.
    Hosted agent runtime principal The actual principal discovered for the deployed agent; receives the runtime grants below.
    Signed-in application user Invokes Foundry through UI OBO and separately needs source/document authorization.

    Frontend Container App

    Bicep assigns the following roles to the frontend's managed identity at the listed resource scopes when those services are selected. Use its actual principal ID, whether system-assigned or an approved user-assigned identity.

    Role Scope Purpose
    App Configuration Data Reader Application configuration store Read runtime keys and Key Vault references.
    AcrPull Application container registry Pull the UI image.
    Key Vault Secrets User Application Key Vault Resolve UI credentials and other configured secret references.
    Storage Blob Data Reader Application Blob storage account Read referenced document blobs.
    Storage Blob Delegator Application Blob storage account Obtain delegation keys for supported Blob links.

    The default frontend role list does not include Search index access, model inference or application Cosmos DB access. Its delegated Foundry calls use the signed-in user's token; granting these services to the UI identity does not fix a denied user call.

    Hosted agent runtime

    After agent deployment, the hosted access reconciliation discovers the actual runtime principal, then applies this closed grant set:

    Role Scope Condition
    App Configuration Data Reader Selected application configuration store Runtime configuration.
    Cognitive Services OpenAI User Selected Foundry account Direct model calls from the supplied runtime.
    Key Vault Secrets User Exact secret referenced by AUDIT_HMAC_KEY Only when the audit key is configured as a Key Vault reference.

    These are not a blanket grant to every secret, source or tool. Reconciliation does not automatically grant arbitrary source access or authorize application users. Review the intended assignments without writing them:

    python -m config.deployment.hosted_access --azd-env --plan

    Run this from the platform root with the prepared Python environment and intended azd environment selected. Use the hosted access bootstrap/recovery procedure for approved reconciliation. Do not substitute the UI or project identity when the runtime principal cannot be discovered.

    Foundry project, Search and image pull

    Bicep creates these cross-service assignments when the associated services are enabled:

    Assignee Role Scope
    Foundry project managed identity AcrPull Hosted image registry using standard RBAC. For an external ABAC-mode registry, Container Registry Repository Reader is used instead.
    Foundry project managed identity Search Index Data Reader Selected Azure AI Search service.
    Foundry project managed identity Storage Blob Data Reader Selected grounding Blob storage account.
    Search managed identity Storage Blob Data Reader Selected grounding Blob storage account.
    Search managed identity Cognitive Services User Selected Foundry account for configured AI services/vectorizers.

    The registry grant allows Foundry to pull the hosted image; it does not authorize the running agent to read application data. Likewise, ingestion or project connection access does not prove per-user retrieval filtering. Sign-in and document access describes the missing hosted retrieval identity integration.

    Deployment operator and pipeline

    An administrator must authorize resource deployment and role assignment before provisioning. Runtime roles do not supply these permissions.

    Operation Access to arrange
    Deploy resources Contributor-equivalent deployment actions on each approved destination and any required parent/shared scope. Creating missing groups also requires subscription-level resource-group creation permission.
    Create role assignments Scoped role-assignment authority wherever Bicep or hosted hooks create grants. Contributor alone cannot create role assignments.
    Configure and build App Configuration Data Owner; the selected Key Vault secret-management, Search configuration/index, model and registry/build permissions. Bicep grants selected service roles to the configured executor, but the operator must already be able to deploy those assignments.
    Author hosted agents Foundry User-equivalent authoring on the exact project, plus account read access. The default Bicep configuration grants Foundry Project Manager when hosted prerequisites and grantHostedAgentProjectManager are enabled; disabling that grant requires separately arranged authoring access.

    Foundry roles might still display their former Azure AI names during the service rename. Cognitive Services User/OpenAI User alone do not authorize hosted-agent authoring. A subscription Owner assignment is not the default solution to a missing data-plane permission.

    Default Agent environments use separate Foundry/root, application and network resource groups. Review the destination scopes and, for pipelines, the service-connection permissions. Reused resources can require additional owner-approved grants outside those groups.

    An optional jumpbox managed identity is a deployment/configuration runner, not the frontend or chat user. Its grants depend on the enabled services and registry authorization mode. Review its effective assignments for the actual deployment rather than copying all operator roles to every runtime identity.

    Application users and optional integrations

    Entra registration/consent, UI admission, Foundry caller access and document access are separate checks. They are not automatically granted to every application user by provisioning. Complete the ordered login setup. Foundry Agent Consumer is the least-privilege built-in role for endpoint-only callers; use the intended agent or project scope.

    Optional ingestion, administrative panel, custom tools and protected sources need their own reviewed grants and integration. Do not add Cosmos or tool permissions to the default UI merely because another topology uses them. See the capability readiness matrix and capability profiles.
