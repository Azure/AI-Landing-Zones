    Images and voice

    Agent Application can answer questions about image descriptions extracted from documents. Choose the document-processing path below. Direct image input and voice require an application extension.

    Choose a scenario

    You want to… Shipped hosted path
    Ask about diagrams in a shared document collection Native Foundry IQ Blob ingestion can verbalize images; the hosted agent retrieves the resulting content through the knowledge base.
    Attach a document to this conversation Optional Agent App Ingestion processes PDF uploads. This is conversation-scoped retrieval, not direct image input to the model.
    Paste a screenshot and ask the model to inspect it Not implemented by Agent Application's hosted adapter. Its Responses input is text-only; the UI upload handler accepts PDFs, not standalone images.
    Speak to the agent or receive spoken answers Requires a custom voice flow connecting Agent App UI and the hosted adapter to audio services.

    Use the hosted default strategy, maf_lite, for these recipes. The classic multimodal strategy is rejected by the hosted runtime.

    Ground answers in document images

    Result: a text answer grounded in content extracted from documents, including image descriptions. The model receives retrieved text.

    Before starting, use a working hosted deployment with Foundry IQ retrieval. You need deployment/configuration access, permission to upload test documents to the configured Blob container, and an approved test document with a clearly identifiable diagram. Use a test environment for model or ingestion changes. The Search ingestion identity needs source/model access independently of the signed-in user's retrieval access. In private deployments, follow Network isolation for connected-runner and native Blob connectivity checks. Retain source permissions and delegated-user retrieval throughout allow/deny testing.

    1. Select native Blob ingestion before following the full-stack deployment workflow:

      azd env set RETRIEVAL_BACKEND foundry_iq
azd env set FOUNDRY_IQ_PATTERN azureBlob
azd env set FOUNDRY_IQ_KNOWLEDGE_SOURCE_KIND azureBlob
azd env set FOUNDRY_IQ_CONTENT_EXTRACTION_MODE standard

    2. Check the deployed model and extraction prerequisites. The shipped template enables image verbalization and supplies a chat completion model only for its supported Content Understanding model names. gpt-4.1 is one supported choice; the checked-in default chat model, gpt-5-nano, is not in that template allowlist. Select a model in that allowlist for image verbalization. Use the model configuration and Microsoft's Blob knowledge source prerequisites to select an available model/version and supported Content Understanding region. Standard extraction also needs the Foundry AI Services endpoint and an embedding deployment. In the checked-in main.parameters.json, the chat entry in modelDeploymentList has canonical_name: CHAT_DEPLOYMENT_NAME: its model.name is the model family, while its name is the deployment name. Keep the selected model version and regional quota compatible with that entry.

    3. Apply changes through the full deployment workflow. Inspect the provisioned Blob knowledge source: expect contentExtractionMode to be standard, disableImageVerbalization to be false, and a non-null chatCompletionModel bound to the intended deployment. Native Blob ingestion does not require the optional ingestion Container App.
    4. Upload the approved document to the configured source container/folder and wait for its ingestion to complete. Ask a specific question whose answer depends on the diagram, not just its surrounding prose.
    5. Check the answer against the diagram and open its source reference. Repeat as a user denied access to the document. Inspect retrieved document IDs and confirm that the document, its content and its citation are absent.

    Microsoft's service documentation can describe newer API capabilities than the pinned release. Keep the release's API configuration unless a coordinated compatibility change has been validated.

    Attach a PDF to a conversation

    Result: the PDF is ingested and retrieved as text within the caller's conversation. Start with a text-bearing PDF. For a scanned PDF or a diagram-only page, check the extracted content before testing retrieval.

    1. Follow Ingestion and conversation uploads to select DEPLOY_INGESTION_CONTAINER_APP=true through the full deployment workflow. Fresh Agent Application deployments default to false, which hides and rejects uploads.

    2. For a native Blob primary source, configure the Foundry IQ conversation-upload source as well: FOUNDRY_IQ_CONVERSATION_UPLOAD_ENABLED=true and a provisioned FOUNDRY_IQ_CONVERSATION_KNOWLEDGE_SOURCE_NAME. Retain the pinned 2026-05-01-preview API required by this upload filter. This source connects processed uploads to knowledge-base retrieval. The source name identifies the registered knowledge source, not a URL or conversation ID. Runtime settings use App Configuration label agent-lz; configure them separately from azd env set deployment inputs. An operator with App Configuration data-write permission can set the nonsecret opt-in using Entra authentication (replace <store-name> with the store name, not its endpoint):

      az appconfig kv set --name "<store-name>" --auth-mode login --label agent-lz --key FOUNDRY_IQ_CONVERSATION_UPLOAD_ENABLED --value true

      Retain the provisioned source name and rerun the full workflow to reconcile the knowledge source and deploy the affected components with the updated settings. 3. Sign in with an eligible user and send a text message first to establish the hosted conversation identifier. Attach a small PDF and ask a question specific to its contents. The handler accepts at most five PDFs, 15 MiB each and 25 MiB combined. Anonymous Copilot sessions cannot upload. 4. Expect a processed-files confirmation and an answer grounded in that PDF. Test a different user's conversation to confirm the upload is not exposed.

    Agent App Ingestion also has a MULTIMODAL setting for extracting and captioning figures in its own pipeline. It is separate from the classic multimodal strategy and native Blob processing. Screenshot input still requires the extension described below.

    Diagnose a missing image answer

    • No attachment control: check the effective ingestion selection first. Native Blob ingestion alone never enables conversation uploads.
    • PDF processing failed: the UI does not send the question after an ingestion failure. Reattach the PDF and retry after resolving the reported ingestion problem; retain the UI's reference ID for support.
    • PDF processed, but answer uses only the shared collection: verify the conversation-upload knowledge source, conversation ID and authenticated caller ownership. The optional upload source can be skipped or fail without failing shared-corpus retrieval. Confirm the returned references include the uploaded PDF.
    • Diagram missing from the answer: check ingestion completion, extracted content and the provisioned chat model binding before changing prompts. An unsupported model name can leave the Blob source's chatCompletionModel null.

    Record the previous model/source settings before changing them. Restore those inputs and rerun the matching full workflow to undo a configuration experiment, keeping indexes and documents intact. Provisioning-managed settings can overwrite portal edits. Runtime settings load at startup: deploy a new hosted agent version and reload the affected UI/ingestion services through the documented deployment workflow. See Configuration and Hosted agents.

    Direct images or voice need an Agent Application extension

    For screenshot inspection, extend the caller and hosted adapter to validate and forward image content to a compatible model. The shipped adapter accepts text only. See Microsoft's vision input guide.

    For voice, build a client/service integration for capture, transcription or realtime audio and playback. Microsoft's Realtime audio guide describes the service APIs for that extension. Use Build your own application for the extension boundary. Preserve user authentication, OBO and source authorization when connecting either extension to retrieval.
