            Public rates and sourced estimates

            The catalog combines Azure Retail Prices API records with automatically captured official pricing-page rows, not a live quote. The gpt-5-nano Global token rates and dedicated ACR S1 allocation rate come from exact published HTML rows, recorded with source and capture date separately from API meters. Resource details identify each source and billing unit. Operator-entered amounts are labelled separately.

            Automated daily refresh publishes only a validated catalog. If collection, exact-row parsing or validation fails, the last validated catalog remains in use. Check the displayed snapshot date and any stale-data warning before relying on an estimate.

            730 hours is an editable monthly convention, not a deployment default. Daily meters use hours ÷ 24. Dedicated ACR pool allocation is billed even without active builds. Hosted allocation hours are a separate billing hypothesis, not a concurrency guarantee.

            Budget for your selected scope

            The inventory includes Foundry backing dependencies, application services, management networking and optional integrations. Structural configuration and shared compute must not be billed twice. Quantity zero means an option is not allocated in this scenario, not that it is free when enabled.

            Review each row's included billing units and assumptions. Contract-priced options use your editable, sourced USD amounts. Additional model/tool use, ingestion, retrieval features, storage operations, retention, transfer and separately licensed services can change the bill.

            Public rates do not incorporate your agreement, negotiated discounts, credits, taxes or currency conversion. Confirm availability, offer terms and the full selected scope with Azure Pricing Calculator or your account team. A difference from the reference is meaningful only with comparable scope and assumptions.

            Reference billing hypotheses & regional differences

            The fresh Foundry backing Cosmos DB account uses provisioned throughput. Its budget example assumes five manual 1,000-RU/s offers (5,000 RU/s total), 10 GB of transactional data plus indexes, a separate 10 GB of Continuous30Days backup and one non-zone-redundant region. This is a $296.50/month hypothesis at the captured rates, not a declaration of deployed offers. The Foundry runtime owns the actual offers.

            The backup selector is also a billing hypothesis: pinned Bicep AVM inherits Continuous30Days, while Terraform omits the backup policy and receives the API's periodic default. Selecting a backup hypothesis here does not change either provider or establish deployed parity.

            East US 2 starts with the shipped Basic Firewall choice. For Sweden Central, no VNet Basic Firewall rate was found in the Retail API or official Basic pricing row; a secured-vHub rate is a different topology and is not substituted. The planner offers Standard/Premium there and uses Standard as its regional reference. Deploying that reference needs a reviewed IaC change; it is not the shipped Basic default.

            See price calculations and budget assumptions for the initial token and build-pool examples. Refreshed rates and their dates are recorded in the catalog.

            This planner models network-isolated standalone deployments. The reference uses hosted-no-panel, native Foundry IQ ingestion, no separate Agent Application Cosmos DB and no Agent App Ingestion worker. Foundry backing services are separate resources. Review deployment choices, sizing and capacity and cost planning before translating a scenario into reviewed infrastructure changes.
